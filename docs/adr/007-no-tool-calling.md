# ADR-007: Tool Calling 배제 — KB는 사전 주입한다

- 상태: 승인 (§7 선배제의 확정 기록)
- 날짜: 2026-09-01

## 배경

Spring AI는 tool calling을 지원한다. KB 인물 조회를 LLM이 필요할 때 도구로 호출하게 만들 수도 있다.
"LLM이 스스로 판단해 조회한다"는 그림이 매력적으로 보이는 자리라 배제 근거를 기록한다.

## 선택지

1. **결정적 사전 주입 (현행)** — NER→링킹→프롬프트 조립을 LLM 호출 전에 끝낸다
2. KB lookup을 tool로 노출 — LLM이 번역 중 필요 인물을 조회
3. 하이브리드 — 사전 주입 + 부족 시 tool 호출

## 결정

**선택지 1.** 근거:

- 전처리 전체(NER+링킹+조립)가 **~25ms, 비용 0, 결정적**이다 (실측). tool calling은 왕복이 최소 2회(초회 생성→tool 결과→재생성)라 지연·토큰이 배로 늘고, 배치 5만+ 건에서 이는 곧 quota다 (전체 p95의 99.7%+가 LLM 왕복 — 왕복을 늘리는 설계는 역주행).
- **재현성**: 같은 입력 = 같은 프롬프트여야 M3 캐시 키·회귀 비교(ADR-013)가 성립한다. 어떤 인물을 언제 조회할지 LLM 재량에 맡기면 같은 입력이 다른 tool 시퀀스를 타서 평가 자체가 무너진다.

## 버린 대안과 그 이유

- **tool 노출(2)**: 조회 필요 여부를 우리가 이미 안다 — NER이 PER를 결정적으로 뽑는다. 아는 것을 LLM더러 다시 알아내게 하는 구조는 비용만 낸다.
- **하이브리드(3)**: "부족 시"의 판정 주체가 다시 LLM이라 (2)의 비결정성이 그대로 남는다.

## 재검토 조건

- 입력이 정형 단문 번역이 아니라 자유 질의(대화형 연구 보조 등)로 바뀌어 사전 NER로 조회 대상을 확정할 수 없게 되면.
