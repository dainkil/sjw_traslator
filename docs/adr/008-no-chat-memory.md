# ADR-008: ChatMemory 배제 — 번역 job은 대화가 아니다

- 상태: 승인 (§7 선배제의 확정 기록)
- 날짜: 2026-09-01

## 배경

Spring AI의 ChatMemory 어드바이저는 이전 대화를 다음 프롬프트에 주입한다.
승정원일기 배치 번역에서 "앞 문장들의 번역이 뒤 문장의 문맥"이라는 가설로 도입할 여지가 있어 보인다.

## 선택지

1. **무기억 — job 독립 (현행)**
2. ChatMemory로 세션 문맥 유지
3. 문서 단위 결정적 문맥 주입 — 앞 문장 원문/번역 n개를 프롬프트에 고정 포함

## 결정

**선택지 1.** 근거:

- 각 job은 독립 단문 번역이다. 승정원일기 기사 다수가 단문 정형문(제수·전교)이라 문장 간 의존이 약하다.
- 입력 토큰의 **85%가 이미 오버헤드**(실측 820 중 ~700). 메모리 주입은 이 비율을 더 키우는데, 비용 절감이 목표인 프로젝트에서 검증 안 된 품질 가설에 토큰을 태울 수 없다.
- **멱등성과 충돌**: 프롬프트가 이전 처리 이력에 의존하면 같은 입력 = 같은 프롬프트가 깨져 M3 캐시 키·재개 시 재현·회귀 비교가 전부 무너진다. 순서 의존이 생기는 순간 병렬 소비와 실패 후 재개(M2의 핵심)도 순서 보장 문제로 바뀐다.

## 버린 대안과 그 이유

- **ChatMemory(2)**: 대화 상태 관리 도구를 배치 파이프라인에 넣는 범주 오류. 메모리 내용이 비결정적으로 누적된다.
- **결정적 문맥 주입(3)**: 유일하게 진지한 대안. 그러나 품질 이득이 실측된 바 없고, 순서 의존성 비용은 확정적이다. 이득이 실측되면 ChatMemory가 아니라 이 방식으로 도입한다 (아래).

## 재검토 조건

- 품질 게이트(§5.4) 가동 후, 오역 원인 분석에서 문장 간 문맥 부족이 주요 원인으로 실측되면 — 그때도 선택지 3(결정적 주입)으로 재검토하며 ChatMemory는 대상이 아니다.
