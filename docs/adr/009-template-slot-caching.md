# ADR-009: 템플릿 슬롯 캐싱 및 KB 버저닝 무효화 전략 (§5.2)

- 상태: 승인 (M3-S1)
- 날짜: 2026-09-01

## 배경

M3의 2단 캐시(L1 원문 완전 일치 / L2 템플릿 구조 일치)는 LLM 호출 자체를 제거하는
최대 절감 레버지만, 계획서 §5.2가 명시한 난제를 먼저 결정해야 한다:

1. **KB 갱신 시 무효화** — 인물 레코드가 수정되면 어떤 캐시가 무효화되어야 하는가.
   KB 수정의 현실적 사유는 대부분 **오링크 교정**이므로, 교정 전 결과가 캐시에 잔존해
   계속 서빙되는 것이 최악의 실패 모드다.
2. **재주입 시 한국어 조사 처리** — 슬롯의 인명이 바뀌면 뒤따르는 조사(이/가 등)의
   받침 일치가 깨진다.
3. **재주입 결과의 검증** — L2 히트는 LLM이 생성하지 않은 문장이다. 품질 증거가 필요하다.

전제(M2.5): `kb_version`·`prompt_version`은 파일 체크섬 파생값이라 데이터가 바뀌면 값이
반드시 바뀐다 (ADR-023). 품질 게이트(ADR-019)가 결과마다 `quality_grade`를 판정한다.

## 선택지

**무효화:**
1. **A. 버전을 캐시 키에 포함** — KB·프롬프트가 바뀌면 키가 달라져 전면 무효화. 코드 0줄
2. B. 엔티티 ID → 캐시 키 역참조 인덱스 — 수정된 인물이 걸린 엔트리만 정밀 무효화
3. C. TTL만 — 시간이 지나면 알아서 소멸

**슬롯 범위:** 확정 PER만 / PER+POS+DAT 전부

## 결정

**무효화는 A안: `cache:l1:{kb_version}:{prompt_version}:{normalized_hash}`,
`cache:l2:{kb_version}:{prompt_version}:{template_hash}`.**

- §8.3 초안은 L1 키에 버전이 없었으나 **L1에도 버전을 넣는다**. L1 값에는 번역문뿐 아니라
  KB 파생물(링크된 엔티티, resolvedName)이 통째로 들어 있고, KB 갱신 = 오링크 교정이라면
  L1의 교정 전 결과 잔존이 정확히 배경 1의 실패 모드다. prompt_version도 같은 이유 —
  프롬프트 개정 후 옛 스타일 결과가 서빙되면 기준선 비교(§5.4)가 오염된다.
- 버전이 체크섬 파생이므로 무효화는 **배포·재기동 없이 키 변경으로 저절로** 일어난다.
  옛 버전의 고아 엔트리는 TTL 30일이 회수한다 (TTL은 정확성 장치가 아니라 메모리 위생).
- **슬롯 범위는 링크 확정 PER만 (v1).** 재주입의 안전성은 "이 자리에 들어갈 문자열"을
  결정론적으로 아는 데서 나오는데, 그 답(KB 확정 한글명)을 가진 타입이 PER뿐이다.
  POS·DAT는 결정론적 한국어 대역이 없어 문면 그대로 템플릿에 남는다.
- **적재 정책이 품질 방어선이다**: L1은 게이트 통과분만(VERIFIED/DEGRADED — 등급 보존,
  REJECTED 미적재), L2는 **VERIFIED + 모든 슬롯의 한글명 전체형이 번역문에 출현**할 때만.
  게이트가 이름부 일치("문회")도 반영으로 인정하는 것과 달리, 템플릿화는 인명 구간을
  특정해야 하므로 전체형만 허용한다 (보수적 적재 = 히트율을 조금 버리고 안전을 산다).
- **조사 보정 (배경 2)**: 마커 바로 뒤의 조사 5쌍(이/가, 을/를, 은/는, 과/와, 이라/라)을
  새 인명의 받침에 맞게 교정한다. 단음절 조사는 뒤가 한글이면 다음 단어의 첫 글자일 수
  있어("○○이조판서") 경계(공백·구두점·문장 끝)일 때만 보정한다. 구조 불일치(마커
  누락·잔존)는 히트 취소 → MISS로 전체 파이프라인 fallback (M3 수용 기준).
- **L1 키에 모델은 넣지 않는다.** 모델 선택은 서버 몫이고(클라이언트 계약 아님), 적재가
  게이트 통과분뿐이라 품질 하한이 이미 보장된다. 생산 모델은 값의 meta에 보존해 반환한다.
- L2 히트 결과는 `DEGRADED`로 표시하고(§5.4 표), **기본 off, 명시 opt-in** — §5.4 비열등
  임계(chrF −2.0, 확정 인명 재현율 하락 0)를 통과해야 켠다 (배경 3, M3-S5에서 실측).

## 버린 대안과 그 이유

- **B(역참조 인덱스)**: 엔트리마다 걸린 인물 ID 색인을 유지하는 쓰기 비용·복잡도를 지는데,
  KB 갱신은 파일 교체 단위의 드문 이벤트다. 정밀 무효화가 아끼는 것은 "갱신 직후의 캐시
  워밍 비용"뿐이고, 이 시스템의 히트 대상(의례 정형문)은 재적재가 싸다. 수혜 없는 정밀함.
- **C(TTL만)**: "언젠가 사라진다"는 정확성 보장이 아니다. 오링크 교정 후에도 TTL 만료까지
  잘못된 인명이 서빙된다 — 배경 1을 정면으로 위반.
- **PER 외 타입 슬롯화**: POS를 슬롯화하면 히트율은 오르지만 재주입할 한국어 관직명의
  정본이 없다 (같은 관직도 문맥별 역어가 갈린다). 잘못된 재주입은 캐시가 아니라 오역 생성기다.

## 재검토 조건

- KB가 부분 갱신(개별 인물 교정)을 자주 받는 운영 단계에 들어가면 B안 재평가.
- L2 표본 재검증(§5.4)에서 조사 보정 실패·재주입 오류가 관측되면 보정 규칙 확장 또는 L2 축소.
- 관직 역어 사전이 생기면(연구 확장) POS 슬롯화 재평가.
