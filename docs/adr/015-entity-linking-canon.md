# ADR-015: 엔티티 링킹 정본 결정 (README 기술 vs 실제 코드 불일치)

- 상태: 승인
- 날짜: 2026-08-31

## 배경

저장소 재편 중 선행 연구 README가 기술하는 "3단계 Fallback 링킹(표층형 완전 일치 → 글자 교집합 → 글자 합집합)"이 **코드로 구현된 적이 없음**을 확인했다. 트리 안의 실제 링킹 구현은 3종이었다:

1. `malmoi/kb/data_ContextInjection.py` — 역색인 후보 생성 → 활동시기 필터(`활동_시작 <= 문서 연도`) → 관직명-문맥 매칭. 모호 시 상위 3후보 + 경고 반환.
2. `malmoi/ex3/run_fixed_kbinject.py`의 `link_entity` — `candidates[0]`을 취하는 퇴화 버전 (실험 편의용).
3. `research/04_ablation/run_kbinject.py`의 `resolve_entity` — person_map/id_lookup 단순 조회.

계획서 §1.1은 "3단계 Fallback 로직 그대로 이식"을 명시하므로, 무엇이 "그대로"의 대상인지 정본을 정해야 했다.

## 선택지

1. **실제 코드(`data_ContextInjection.py`)를 정본으로 채택** — 검증된 로직을 이식하고 README 불일치를 문서화.
2. **README 기술대로 신규 구현** — 문서와 코드를 일치시키지만, 한 번도 실행·검증된 적 없는 알고리즘을 새로 작성.
3. **M1에서 두 방식을 골든셋으로 비교 후 채택** — 가장 방어 가능하나 M1 기간 증가.

## 결정

**선택지 1 채택** (사용자 결정, 2026-08-31). `kb/data_ContextInjection.py`의 3단계(후보 생성 → 시간 필터 → 관직 매칭)를 서빙 정본으로 이식한다.

근거:
- 계획서 원칙 4("모든 주장은 실측 기반") — 실행 이력이 있는 코드가 문서상의 알고리즘보다 우선한다.
- 이 로직의 부산물(어느 단계에서 해소됐는지, 복수 후보 여부)이 그대로 티어 라우팅(§5.1)의 신호가 된다.
- 모호 시 "상위 3후보 + 플래그" 반환은 T2 라우팅의 트리거로 재사용 가능.

부수 조치: README 재작성 시 링킹 기술을 실제 알고리즘으로 교정한다.

## 버린 대안과 그 이유

- **README대로 신규 구현(2)**: 글자 교집합/합집합 매칭은 표기 변형(약칭 馨長 → 李馨長)에 대응하려는 아이디어로 보이나, 구현·평가된 적이 없어 채택 시 "실측 기반" 원칙을 스스로 위반한다. 아이디어 자체는 유효할 수 있어 재검토 조건에 남긴다.
- **M1 비교 실험(3)**: 링킹은 서빙 시스템의 차별화 축이 아니라 입력 신호 공급자다. 여기에 실험 예산을 쓰면 계획서 §13의 "범위 확대로 미완성" 리스크를 키운다.

## 재검토 조건

- 인조 1년치 배치 실측에서 KB 미매칭(`KB_MISS`) 비율이 유의하게 높고, 그 다수가 약칭·표기 변형으로 확인되면 글자 단위 fallback을 4단계로 추가하는 실험을 M4 이후 검토한다.
