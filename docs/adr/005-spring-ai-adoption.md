# ADR-005: Spring AI 채택 및 버전(2.0.0 GA) 선택

- 상태: 승인 (M1에서 구현 완료, E2E 검증 후 확정)
- 날짜: 2026-08-31

## 배경

LLM 연동을 WebClient 직접 호출로 할지, Spring AI 추상화로 할지, 그리고 Spring AI라면 1.1.x(Boot 3)와 2.0.0 GA(Boot 4, 2026-06-12 릴리스) 중 무엇을 쓸지. (계획서 §4.2, §4.4)

## 선택지

1. **Spring AI 2.0.0 GA** (Boot 4.1)
2. Spring AI 1.1.x (Boot 3.x, 보수적)
3. WebClient/RestClient로 Gemini REST 직접 호출

## 결정

**선택지 1.** 근거:

- **ChatClient 추상화가 실험 설계의 일부다.** 선행 연구의 명시된 한계 — "Gemini 2.5 Flash 자체 품질이 높아 KB 주입의 차별 기여가 좁다" — 는 더 약한/다른 모델로의 교체 실험을 요구하고, M4 티어 라우팅은 티어별 모델 매핑을 요구한다. provider 교체가 설정 수준으로 내려간다.
- `PromptTemplate`(프롬프트 버전 관리), `BeanOutputConverter`(정규식 후처리 → 스키마 보장), Micrometer 토큰 계측(비용 SLI의 데이터 소스)을 직접 구현 없이 얻는다.
- 신규 프로젝트라 레거시 제약이 없고, 2.0.0은 GA다.
- 구현 결과: M1 파이프라인이 2.0.0에서 첫 컴파일에 통과했고 컨텍스트 로드 정상 (`api/`).

설정상 주의(§4.3): Developer API 모드에서는 `spring.ai.google.genai.api-key`만 설정한다. `project-id`/`location`을 넣으면 Vertex 모드로 전환되어 키가 400으로 거부된다.

## 버린 대안과 그 이유

- **1.1.x(2)**: 안정성은 높지만 Boot 3 고정. 신규 프로젝트가 구세대 스택으로 시작할 이유가 없다. 단, 2.0 생태계 미성숙으로 블로커가 나오면 여기로 폴백한다(아래 재검토 조건).
- **직접 호출(3)**: 의존성 하나가 줄지만 토큰 계측·구조화 출력·재시도 연동·provider 교체를 전부 수작업으로 재구현하게 된다. 특히 토큰 계측은 비용 SLI(§5.3)의 원천이라 포기 불가. "Spring AI를 안 썼다면?"이라는 면접 질문의 답이 이 문단이다.

## 재검토 조건

- 2.0.0에서 google-genai 스타터의 기능 결함/블로커 발견 시 1.1.x로 폴백하고 이 문서에 경위를 추가한다.
- Gemini 2.5 계열 은퇴 공지 시 모델 교체(설정 변경)로 대응 — 이 추상화의 실증 사례로 기록한다.
