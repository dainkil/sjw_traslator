## 모델이 드러낸 구조적 사실 2가지

1. **입력 토큰의 ~88%가 프롬프트 오버헤드다** (호출당 입력 ~1,364 tok 중 1,200 tok이 페르소나·예시·KB 블록).
   원문 자체는 평균 164 tok에 불과하다. 따라서 비용 절감의 1순위 레버는 번역 결과 캐싱 이전에 **프롬프트 다이어트와 컨텍스트 캐싱**(Gemini cached input $0.03/M — 일반 입력의 1/10)이다. → M1에서 프롬프트 고정부를 context cache로 분리하는 실험을 추가한다.
2. **벽시계 시간은 지연이 아니라 quota가 지배할 것이다.** 동시성 50 × 2s면 이론상 25 rps지만, 실제 상한은 Gemini의 RPM/TPM quota다. 이 모델은 quota를 반영하지 않으므로 벽시계 수치는 하한값이다. M2의 적응형 rate control 실측으로 유효 처리량을 확정한다.

## 리스크

- **Gemini 2.5 계열 은퇴**: 공식 deprecations 페이지 확인 결과(2026-08-31) `gemini-2.5-flash`는 **은퇴일 미공지** — 웹에 돌던 2026-10-16설은 공식 아님. 기본 티어 유지. 단, Gemini 3.x 계열(3.5/3.6/3.7-flash)이 활성 라인이므로 은퇴 공지 시 ChatClient 추상화(ADR-005)로 교체하고 단가 파라미터만 갱신한다. 3.x는 M4 티어 라우팅의 모델 후보이기도 하다.
- 문장 분할 단위가 선행 코퍼스와 다르면 문장 수 산정이 달라진다. `avg_src_chars_per_sentence`가 이를 흡수한다.

| 파라미터 | 교체 시점 | 방법 |
|---|---|---|
| 토큰/자 비율, 프롬프트 오버헤드 | M1 | `countTokens` API로 골든셋 300문장 실측 |
| 호출 지연 | M1 | 단계별 지연 분해 (§2.1) |
| 재시도율, 유효 처리량 | M2 | 인조 1년치 배치 실행 |
| 캐시 히트율 | M3 | L1/L2 on/off 비교 |
