## 기준 시나리오 산출 (토큰 실측 반영, 2026-08-31 — 지연·재시도율·환율은 아직 추정)

| 시나리오 | 총 비용 | 문장당 | 벽시계 |
|---|---|---|---|

| **캐시 17.4% (M3 실측)** | **$695 ≈ 97만 원** | 0.8원 | 0.7일 |

| ~~캐시 40% + 배치 할인~~ | ~~$253 ≈ 35만 원~~ | | 히트율 40%는 **실측으로 반증됐다**(17.4%) — 위 행으로 교체 |
| Flash-Lite 단가 기준, 캐시 0% | $177 ≈ 25만 원 | 0.2원 | 0.9일 |

| 무료 티어 — 3.5-flash 단독 | 0원 | 0원 | RPD 20 실측 기준 173년 → 캐시 반영 143년 (T1 최악 조건) |

> **M3 실측이 바꾼 것 (2026-09-11).** 캐시 히트율 가정 40%는 반증됐다 — 인조 전수 실측 17.4%다.
> 캐시만으로는 무료 축이 173년 → 143년으로 17%밖에 줄지 않는다. **완역 시간의 지배 변수는 캐시가
> 아니라 quota이고, 남은 레버는 티어 라우팅(M4 = 모델별 quota 풀링)이다.** 히트율은 배치 규모에
> 종속되며(5천문장 12.5% → 6.2만문장 15.7%, 상승 중) 잔여 약 120만 문장에서는 더 오를 것으로
> 보이나, 40%에 이를 근거는 없다. 측정 전 가정이 레버의 우선순위를 잘못 잡고 있었다.

> **무료 축 대폭 수정 (2026-09-11, M3-S5).** 개발 기본 모델 `gemini-3.1-flash-lite`의 무료 quota를
> 실측했다 — **RPD 500 / RPM 15** (429 응답 `quotaValue`, 3.5-flash RPD 20을 확정한 것과 같은 방법).
> 헤드라인 173년은 **RPD 20짜리 T1 모델 단독**이라는 최악 조건이었고, 실제 운영 모델로는 **6.9년**
> (캐시 17.4% 반영 **5.7년**)이다. 25배 차이가 "어느 모델의 quota를 쓰는가"에서 나온다.
> **이것이 M4 티어 라우팅의 값을 구체화한다**: 모델별 quota가 독립이므로 풀링하면 500 + 20 + (gemma-4 미측정)이
> 하루 예산이 되고, 완역 시간은 캐시가 아니라 이 합계가 정한다. 일 500회면 3년치 인조 코퍼스(약 6.2만 문장)를
> 넉 달에 처리한다 — 검증 배치가 현실적 규모로 내려온다.
>
> **이 대비가 프로젝트의 논지다**: 동일 시스템이 무료 quota(T1 단독 최악 조건)로는 173년, 118만 원이면 하루 안에 끝난다.
> 운영은 무료 티어로 하되(quota=예산 원장), 유료 시나리오는 파라미터 하나로 재계산되는 counterfactual로 유지한다.
> 무료 축의 단축 수단이 곧 이 시스템의 기능 목록이다: 티어 라우팅=모델별 quota 풀링(M4), 템플릿 캐싱=호출 자체 제거(M3).

> 최초 추정(전부 추정 파라미터) 대비 총비용이 $1,191 → $746로 내려갔다. 주 원인은 프롬프트 고정부가
> 추정 1,200tok → 실측 448tok(Gemini 토크나이저가 한국어 페르소나를 예상보다 압축), 한자 토큰/자 1.3 → 0.954.

## 모델이 드러낸 구조적 사실 2가지

1. **입력 토큰의 ~85%가 프롬프트 오버헤드다** (E2E usage 실측: 호출당 입력 ~820 tok = 페르소나 448 + Structured Output 지시문·KB블록 ~250 + 원문 ~120).
   따라서 비용 절감의 1순위 레버는 번역 결과 캐싱 이전에 **프롬프트 다이어트와 컨텍스트 캐싱**(Gemini cached input $0.03/M — 일반 입력의 1/10)이다. → M3에서 고정부 context cache 분리 실험을 함께 다룬다.
2. **벽시계 시간은 지연이 아니라 quota가 지배할 것이다.** 동시성 50 × 2s면 이론상 25 rps지만, 실제 상한은 Gemini의 RPM/TPM quota다. 이 모델은 quota를 반영하지 않으므로 벽시계 수치는 하한값이다. M2의 적응형 rate control 실측으로 유효 처리량을 확정한다.

## 리스크

- **Gemini 2.5 계열 은퇴**: 공식 deprecations 페이지 확인 결과(2026-08-31) `gemini-2.5-flash`는 **은퇴일 미공지** — 웹에 돌던 2026-10-16설은 공식 아님. 기본 티어 유지. 단, Gemini 3.x 계열(3.5/3.6/3.7-flash)이 활성 라인이므로 은퇴 공지 시 ChatClient 추상화(ADR-005)로 교체하고 단가 파라미터만 갱신한다. 3.x는 M4 티어 라우팅의 모델 후보이기도 하다.
- 문장 분할 단위가 선행 코퍼스와 다르면 문장 수 산정이 달라진다. `avg_src_chars_per_sentence`가 이를 흡수한다.
